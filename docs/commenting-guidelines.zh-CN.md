# 注释规范

本仓库的注释目标是帮助开发者快速理解业务意图、状态流转和接口契约，而不是重复代码表面含义。

## C# 成员级注释

- 已纳入注释治理范围的 C# 文件，类、字段和方法都使用中文 XML 文档注释。
- 字段注释说明保存的状态、协作对象、缓存内容或 UI 绑定用途。
- 方法注释说明调用时机、职责、关键副作用，以及调用方需要知道的状态变化。
- 本次不强制为属性、事件和枚举成员逐个补注释，但公共契约仍应保持清晰。

## 公共 API 与契约

- 对 `public` 类型、接口、事件和跨层调用的方法使用 XML 文档注释。
- 注释需要说明用途、关键约束、成功/失败语义，以及调用方需要知道的副作用。
- 如果实现类完全继承接口语义，可以使用 `/// <inheritdoc />`，但实现中有额外重试、回滚、状态同步或异常兜底时要补充实现职责。

## 复杂业务流程

- 对存在事务、并发控制、状态机、锁定/解锁、回调处理、仓库隔离等逻辑的方法，使用少量注释解释“为什么这样做”。
- 注释应贴近关键分段，例如“查询已有锁定记录”“事务内二次校验库位”“回调后同步 UI 状态”。
- 即使成员需要注释，也不为显而易见的赋值、循环、判空逐行写说明。

## XAML 与代码隐藏文件

- XAML 只写结构性注释，用于标识页面区块，例如查询区、操作区、消息区、列表区、进度区。
- code-behind 只说明交互桥接职责，例如焦点切换、回车快捷触发、页面卸载时清理状态。
- 不为控件样式、布局属性或每个绑定表达式逐项注释。

## 禁止事项

- 不新增“把代码翻译成中文”的逐行废话式注释。
- 不保留乱码、过时、误导性或与实际行为不一致的历史注释。
- 不在注释中描述尚未实现的行为；文档必须与当前代码保持一致。
