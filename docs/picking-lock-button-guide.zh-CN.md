# 拣货锁定/解锁按钮功能说明

## 概述

拣货页面（PickingCode）右上角有一个锁定/解锁开关按钮（ToggleSwitch），用于控制当前领料单条码的锁定状态。锁定功能可以防止多个操作员同时操作同一批条码，避免拣货冲突。

## 按钮界面

```
┌─────────────────────────────────────────────────────┐
│  拣货作业                              [锁定中] 🔘  │
│                                                      │
│  领料单号: [____________] [查询]                    │
│  ...                                                 │
└─────────────────────────────────────────────────────┘
```

| 状态 | 显示文本 | 开关位置 |
|------|----------|----------|
| 已锁定 | 锁定中 | 右侧（开启） |
| 已解锁 | 已解锁 | 左侧（关闭） |

## 功能说明

### 锁定状态（锁定中）

当开关处于"锁定中"状态时：
- 当前领料单的条码已被锁定在数据库表 `CUS_PICKING_LOCK_BARNO` 中
- **其他操作员查询同一领料单时，这些条码会被排除**（不会被分配给其他人）
- 确保当前操作员可以独占这些条码进行拣货作业

### 解锁状态（已解锁）

当开关处于"已解锁"状态时：
- 当前领料单的条码锁定记录已从数据库中删除
- 其他操作员可以查询到这些条码并进行拣货

## 使用场景

### 场景 1：正常拣货流程（推荐）

```
1. 输入领料单号 → 点击查询
   ↓
2. 系统自动锁定条码（开关自动变为"锁定中"）
   ↓
3. 进行拣货操作
   ↓
4. 拣货完成后 → 手动点击开关解锁
   ↓
5. 开关变为"已解锁"，其他人员可继续操作
```

**说明**：当前流程已改为"查询即锁定"，查询成功后条码自动锁定。

### 场景 2：临时暂停作业

```
1. 当前正在拣货（锁定中状态）
   ↓
2. 需要临时离开或暂停
   ↓
3. 保持锁定状态，条码不会被其他人抢走
   ↓
4. 返回后继续操作
```

### 场景 3：放弃当前拣货

```
1. 当前正在拣货（锁定中状态）
   ↓
2. 发现无法完成，需要放弃
   ↓
3. 点击开关解锁
   ↓
4. 其他操作员可以接手这批条码
```

### 场景 4：切换领料单

```
1. 当前正在拣货领料单 A（锁定中状态）
   ↓
2. 需要先处理领料单 B
   ↓
3. 输入领料单 B 的单号 → 点击查询
   ↓
4. 系统自动解锁领料单 A，并锁定领料单 B
```

**说明**：查询新单据时，系统会自动解锁旧单据的条码。

## 按钮启用条件

| 条件 | 开关状态 |
|------|----------|
| 列表无数据（未查询或已清空） | 禁用（灰色） |
| 列表有数据（已查询到条码） | 启用（可点击） |

## 涉及的 API 接口

### 1. 查询并锁定（Reserve）

```
POST /api/pick/reserve
```

**说明**：查询领料单时自动调用，返回已锁定的条码列表。

**请求参数**：
```json
{
  "docNo": "领料单号",
  "warehouseLocation": "仓库位置"
}
```

### 2. 手动锁定（Lock）

```
POST /api/pick/lock
```

**说明**：将开关从"已解锁"切换到"锁定中"时调用。

**请求参数**：
```json
{
  "barNoList": [
    {
      "productNo": "产品编号",
      "barNo": "条码",
      "barQty": 10,
      "requiredQty": 5,
      "binNo": "库位"
    }
  ],
  "docNo": "领料单号"
}
```

### 3. 手动解锁（Unlock）

```
POST /api/pick/unlock
```

**说明**：将开关从"锁定中"切换到"已解锁"时调用。

**请求参数**：
```json
{
  "barNoList": [...],
  "docNo": "领料单号"
}
```

## 数据库表结构

锁定记录存储在 `CUS_PICKING_LOCK_BARNO` 表中：

| 字段 | 说明 |
|------|------|
| GUID | 主键 |
| PRODUCT_NO | 产品编号 |
| BAR_NO | 条码号 |
| BAR_QTY | 条码数量 |
| REQUIRED_QTY | 需求数量 |
| BIN_NO | 库位 |
| DOC_NO | 领料单号 |
| CREATE_TIME | 创建时间 |
| CREATOR | 创建者 |

## 注意事项

1. **并发控制**：系统使用数据库事务（Serializable 隔离级别）确保并发安全，不会出现多个操作员锁定同一条码的情况。

2. **自动解锁**：
   - 查询新领料单时，旧领料单的条码会自动解锁
   - 清空列表时，条码会自动解锁

3. **操作失败回滚**：如果锁定/解锁操作失败，开关状态会自动回滚到操作前的状态。

4. **消息提示**：
   - 锁定成功：`条码已锁定，其他人无法查询。`
   - 解锁成功：`条码已解锁。`
   - 操作失败：会显示具体错误原因
